## 3. UML-Klassendiagramm des Backends

Frameworkklassen sind auf die relevanten Mitglieder reduziert. Generische Rückgabetypen sind mit C#-Schreibweise in Anführungszeichen dargestellt; Properties besitzen öffentliche Getter und Setter.

```mermaid
classDiagram
    direction LR
    class ControllerBase {
        <<framework>>
    }
    class EntryController {
        -EntryService _entryService
        +EntryController(EntryService entryService)
        +Get() "Task<IActionResult>"
        +AddEntry(Entry entry) "Task<ActionResult<Entry>>"
    }
    class EntryService {
        -DatabaseContext _databaseContext
        +EntryService(DatabaseContext databaseContext)
        +FindAll() "Task<List<Entry>>"
        +AddEntry(Entry entry) "Task<Entry>"
    }
    class DatabaseContext {
        +DbSet~Entry~ Entries
        +DatabaseContext(DbContextOptions~DatabaseContext~ options)
        #OnModelCreating(ModelBuilder modelBuilder) void
        #OnConfiguring(DbContextOptionsBuilder optionsBuilder) void
    }
    class DbContext {
        <<framework>>
        +SaveChangesAsync() Task~int~
    }
    class Entry {
        <<entity>>
        +int Id
        +DateTime CheckIn
        +DateTime CheckOut
    }
    ControllerBase <|-- EntryController
    DbContext <|-- DatabaseContext
    EntryController --> EntryService : Konstruktorinjektion
    EntryService --> DatabaseContext : Konstruktorinjektion
    DatabaseContext ..> Entry : verwaltet über Entries
    EntryController ..> Entry : Parameter und Antwort
    EntryService ..> Entry : liest und speichert
```


## 4. Entity Relationship Diagram als UML-Klassendiagramm

```mermaid
classDiagram
    class Entry {
        <<table>>
        integer Id
        timestamptz CheckIn
        timestamptz CheckOut
    }
```

| C#-Property | PostgreSQL-Spalte | SQL-Typ | Einschränkungen |
| --- | --- | --- | --- |
| `Id: int` | `"Id"` | `integer` | Primärschlüssel, NOT NULL, GENERATED BY DEFAULT AS IDENTITY |
| `CheckIn: DateTime` | `"CheckIn"` | `timestamp with time zone` | NOT NULL |
| `CheckOut: DateTime` | `"CheckOut"` | `timestamp with time zone` | NOT NULL |

Erwartetes Schema aus EF-Mapping und Npgsql-Konventionen: `public."Entry"`. Es gibt eine fachliche Tabelle und noch keine Fremdschlüssel oder Beziehungen. Die Identity-Sequenz ist keine zusätzliche Entität. Das Schema ist hier aus dem Code abgeleitet; die Abfrage in der README erlaubt den Abgleich mit der laufenden Datenbank.

`ToTable("Entry")` legt den Tabellennamen fest. Gross-/Kleinschreibung erfordert die doppelten Anführungszeichen in SQL. Der Browser sendet mit `toISOString()` UTC-Zeitpunkte (`Z`); Npgsql speichert diese als `timestamp with time zone`. Die ursprüngliche Zeitzone wird dabei nicht gespeichert. Die Anzeige erfolgt über `toLocaleString()` in der lokalen Browser-Zeitzone.

Quellen: [Npgsql Identity-Spalten](https://www.npgsql.org/efcore/modeling/generated-properties.html), [Npgsql Zeitstempel-Mapping](https://www.npgsql.org/efcore/release-notes/6.0.html).

## 5. Sequenzdiagramme

Gezeigt werden erfolgreiche Abläufe. ASP.NET Core übernimmt Routing, JSON-Deserialisierung, Modellvalidierung und Serialisierung; EF Core/Npgsql übernimmt den SQL-Zugriff. Die asynchronen Aufrufe werden jeweils abgewartet.

### 5.1 Zeitbuchung erfassen

```mermaid
sequenceDiagram
    actor Benutzer
    participant Browser
    participant EntryController
    participant EntryService
    participant DatabaseContext as DatabaseContext / EF Core
    participant Datenbank as PostgreSQL
    Benutzer->>Browser: Formular ausfüllen und Save klicken
    Browser->>EntryController: POST /entry, JSON mit checkIn und checkOut
    EntryController->>EntryService: AddEntry(entry)
    EntryService->>DatabaseContext: Entries.Add(entry)
    DatabaseContext-->>EntryService: EntityEntry (Status Added)
    Note over EntryService,DatabaseContext: Add merkt die Entität nur vor, noch kein INSERT
    EntryService->>DatabaseContext: SaveChangesAsync()
    DatabaseContext->>Datenbank: INSERT INTO "Entry" (...) VALUES (...) RETURNING "Id"
    Datenbank-->>DatabaseContext: Generierte Id
    Note over DatabaseContext: Id in Entry übernehmen, Status Unchanged
    DatabaseContext-->>EntryService: Anzahl gespeicherter Zustandseinträge
    EntryService-->>EntryController: Entry mit Id
    EntryController-->>Browser: HTTP 201 Created, JSON und Location-Header
    Browser->>Browser: entries.push(entry), renderEntries()
    Browser-->>Benutzer: Aktualisierte Tabelle anzeigen
```


### 5.2 Zeitbuchungen anzeigen

```mermaid
sequenceDiagram
    actor Benutzer
    participant Browser
    participant Webserver as ASP.NET Core / Static Files
    participant EntryController
    participant EntryService
    participant DatabaseContext as DatabaseContext / EF Core
    participant Datenbank as PostgreSQL
    Benutzer->>Browser: Startseite öffnen
    Browser->>Webserver: GET / sowie script.js und style.css
    Webserver-->>Browser: HTML, JavaScript und CSS
    Browser->>Browser: DOMContentLoaded, indexEntries()
    Browser->>EntryController: GET /entry
    EntryController->>EntryService: FindAll()
    EntryService->>DatabaseContext: Entries.ToListAsync()
    DatabaseContext->>Datenbank: SELECT "Id", "CheckIn", "CheckOut" FROM "Entry"
    Datenbank-->>DatabaseContext: Zeilen
    DatabaseContext-->>EntryService: List of Entry
    EntryService-->>EntryController: List of Entry
    EntryController-->>Browser: HTTP 200 OK, JSON-Liste
    Browser->>Browser: entries setzen, renderEntries()
    Browser-->>Benutzer: Zeitbuchungen in lokaler Zeit anzeigen
```
